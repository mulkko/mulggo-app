# 필터 옵션 vs 실제 데이터 불일치 정리 (2026-09-09)

> `frontend/src/pages/matching/FilterPage.tsx`의 필터 옵션(`FILTER_GROUPS`)이 프로토타입
> 값 그대로라 실제 DB(`announcements` 테이블) 값과 안 맞는 부분을 정리한 문서.
> "기업유형"은 실제 값으로 이미 교체함 (아래 1번). 나머지 3개는 결정이 필요해서
> 건드리지 않고 현황만 정리함.

## 1. 기업유형 (지원대상) — 처리 완료

컬럼: `announcements.target_summary` (bizinfo만 해당 — kstartup은 자유 문장이라 이 필터
적용 대상이 아님)

- 실제 값(9개): 마을기업, 사회적기업, 소상공인, 여성기업, 장애인기업, 제조업, 중소기업, 창업벤처, 협동조합
- 실제 값 기준으로 `FilterPage.tsx` 옵션 교체함 (청소년/대학생/일반인 등 유령 옵션 제거, 여성기업 추가)

## 2. 지원분야 — 미결정, 소스마다 구조가 다름

컬럼: `announcements.category`

| 소스 | 실제 값 | 형태 |
|---|---|---|
| kstartup (11개) | 글로벌, 기술개발(R&D), 멘토링ㆍ컨설팅ㆍ교육, 사업화, 시설ㆍ공간ㆍ보육, 융자ㆍ보증, 인력, 정책자금, 창업교육, 판로ㆍ해외진출, 행사ㆍ네트워크 | 단일 깨끗한 값 |
| bizinfo (8개, 대분류만) | 경영, 금융, 기술, 기타, 내수, 수출, 인력, 창업 | "대분류 > 중분류" 합친 문자열 (예: "창업 > 사업화지원") |

- 겹치는 값이 "인력" 정도뿐. kstartup의 "사업화"/"정책자금"은 bizinfo 대분류엔 없고, bizinfo의 중분류
  (예: "창업 > **사업화지원**")에만 비슷한 의미가 있음.
- 하나의 옵션 목록으로 묶기 애매함 — 결정 필요.

## 3. 사업신청가능업력 — 실제 값이 UI보다 지저분함

컬럼: `announcements.business_age_condition` (kstartup만 값 있음, bizinfo는 전부 NULL)

- 실제 값(12개): 10년미만, 1년미만, 3년미만, 5년미만, 7년미만, 업력무관, 예비창업자,
  예비창업자~10년미만, 예비창업자~1년미만, 예비창업자~3년미만, 예비창업자~5년미만, 예비창업자~7년미만
- 지금 UI(7개, 단일선택): 예비창업자, 1년미만, 2년미만, 3년미만, 5년미만, 7년미만, 10년미만
- 문제:
  - "2년미만"은 실제 데이터에 없음 (유령 옵션)
  - "예비창업자~3년미만"처럼 **예비창업자 여부 + 연차가 합쳐진 값**이 있어서, 단일선택으로
    "예비창업자"와 "3년미만"을 따로 골라도 이 값에 매칭 안 됨

## 4. 사업대상연령 — 실제 값이 UI보다 지저분함

컬럼: `announcements.target_age_groups` (배열, kstartup만 값 있음, bizinfo는 전부 빈 배열)

- 실제 값(10개): 만 15세 이상, 만 19세 이상, 만 19세~39세, 만 20세 이상,
  만 20세 이상 ~ 만 39세 이하, 만 34세 이하, 만 39세 이하, 만 40세 이상, 만 45세 이하, 전연령
- 지금 UI(4개): 전체, 만 20세 미만, 만 20~39세, 만 40세 이상
- 문제: "만 34세 이하", "만 45세 이하" 같은 값은 지금 4개 옵션 중 어디에도 정확히 안 맞음

## 제안 (결정 필요)

2·3·4번은 "깔끔한 카테고리 몇 개"로 미리 묶어두는 방식 자체가 실제 데이터와 안 맞는다.
대안: 가공된 카테고리를 만들지 않고, **실제 distinct 값을 그대로 다중선택 체크박스로 노출**
(예: 업력 필터가 12개 체크박스 그대로). 구현은 더 간단해지지만 UI에 옵션이 많아짐.
