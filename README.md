# mulkko

> 막연한 사업 아이디어는 AI 질문으로 **구체화**하고, 자격 맞는 정부지원사업만 **우대조건 충족순으로 투명하게** 골라주며, 창업 단계 **성장 로드맵**과 **AI 신청서 초안 생성**까지 돕는 서비스

- 팀 6인 · 기간 약 3주 (8/24 – 9/14)
- 1차 시연: 9/15(화) · 2차 시연: 9/16(수) · 본 발표: 9/17(목)

> **작업 시작 전 [`CLAUDE.md`](./CLAUDE.md)를 꼭 확인하세요.** 폴더 구조, 코딩 컨벤션, API 응답 포맷, 프론트엔드 디자인 토큰 규칙 등 이 저장소의 작업 전제가 정리되어 있습니다. (Claude Code 사용 시에는 세션 시작할 때 자동으로 읽어들입니다.)

## 프로젝트 개요

정부·지자체 지원사업은 연간 수천 건이 쏟아지지만, 소상공인·창업자는 자격요건이 제각각이라 되는 것을 못 골라내고 서류 부담 때문에 신청을 포기합니다. 예비창업자는 한발 더 앞서 막혀 있습니다 — 아이디어는 있어도 사업 아이템으로 구체화하지 못해 어떤 지원사업을 봐야 할지조차 모릅니다.

본 서비스는 **아이디어 구체화 → 공고 매칭 → 신청서 작성 → 창업 단계 로드맵**까지, 실시간 공고 데이터와 비정형 자격요건을 사용자와 대조하는 AI 파이프라인 하나로 잇습니다.

## 주요 기능

- 사업 구체화 챗봇 (예비창업자용): 막연한 아이디어를 5가지 질문으로 구체화 → PSST 요약 + 매칭용 프로필 자동 생성
- 아이디어 유사도 분석: 선정 패턴 근접도를 참고 인사이트로 제공
- 프로필 입력: 폼 입력 / 자연어 입력 / 사업자료(PDF·DOCX) 첨부
- 업종 자동매핑 (ML 분류기): 자유텍스트 업종 → 국세청 업종코드(KSIC) 정규화
- 자격 매칭 필터링: 충족 ✓ / 미충족 ✗ / 확인 필요 ? 판정 + 우대조건 충족 개수(N/M) 정렬
- 매칭 재정렬 (지도학습 ML): 임베딩 유사도 + 우대조건 충족 개수 + 마감 임박도 기반 보조 정렬
- 사업자 진단 → 성장 로드맵: NOW / NEXT / LATER로 정리
- AI 신청서 작성 어시스턴트: 신청서 양식 파싱 → 질문 → PSST 초안 생성 → 체크리스트
- 마감 캘린더 · 부족 서류 체크리스트

(확장 기능: 선정 후 사후관리, 업종 트렌드 뉴스 알림)

## 기술 스택

- **Frontend**: React (Vite + TypeScript, 사용자용 화면) + Streamlit (frontend-admin/, 관리자용 화면)
- **Backend**: Python (API 서버)
- **DB**: PostgreSQL 또는 Oracle — **팀 논의 중, 확정 시 업데이트 예정**
- **AI/ML**: LangChain (챗봇·에이전트), RAG(벡터DB), 자체 학습 ML 분류기(업종 매핑), 지도학습 재정렬 모델
- **데이터 소스**: 기업마당(bizinfo) API, K-Startup API, 공고 원문 크롤링/파싱

## 데이터 흐름 & 저장 원칙

**폴더는 코드를 담고, 실제 데이터는 DB에 담습니다.** `crawler/`, `preprocessing/` 같은 폴더에는 데이터 파일이 쌓이는 게 아니라, 데이터를 가져오고 가공하는 "코드(스크립트)"만 들어갑니다.

흐름은 다음과 같습니다:

1. `backend/crawler/` 의 스크립트 실행 → 기업마당·K-Startup API 호출 / 공고 상세 크롤링 → **가공 없이 원본 그대로** DB `raw_listings` 테이블에 저장
2. `backend/preprocessing/` 의 스크립트 실행 → `raw_listings`를 읽어서 자격요건·제출서류 구조화, 첨부자료 파싱 → 결과를 DB `processed_listings` 테이블에 저장

**원본(raw)과 가공본(processed)을 테이블로 분리하는 이유**: 전처리 로직에 버그가 있거나 개선이 필요할 때, 크롤링을 처음부터 다시 하지 않고 저장된 원본으로 재처리만 하면 되기 때문입니다. 크롤링은 페이지가 마감·삭제되면 다시 가져오지 못할 수 있어 원본 보존이 특히 중요합니다.

**`data/` 폴더에는 실제로 이런 것만 들어갑니다** (대용량 크롤링 원본이나 처리된 공고 데이터 전체는 여기 안 들어가고 DB에 저장):
- 작은 정적 참고자료 (예: 국세청 업종 코드표)
- ML 학습용 라벨 데이터 (예: 업종명-KSIC 라벨 데이터, 팀이 직접 구축)
- DB 연결 없이 코드 테스트용 소규모 샘플 데이터

## Git 사용 도구 안내

이 프로젝트는 **GitHub Desktop 사용을 권장**합니다. 터미널 명령어에 익숙하지 않은 팀원도 많아서, 버튼 클릭 기반의 GUI 도구로 진입장벽을 낮추기 위함입니다. (익숙해지면 터미널로 넘어가셔도 무방합니다.)

**옵션 1 — GitHub Desktop** (git 전용 프로그램, 초보자에게 가장 직관적)
- 다운로드: https://desktop.github.com
- 설치 후 깃허브 계정으로 로그인 → "Add local repository"로 clone 받은 `mulkko` 폴더 불러오기
- 브랜치 생성, 커밋, push, Pull Request까지 전부 버튼 클릭으로 가능

**옵션 2 — VSCode Source Control 패널** (에디터 안에서 창 전환 없이 바로 가능)
- VSCode 왼쪽 사이드바의 "Source Control"(가지 모양 아이콘) 클릭
- 화면 맨 아래 왼쪽의 브랜치 이름 클릭 → 브랜치 전환/생성
- 바뀐 파일 옆 "+" 클릭 → 스테이징, 위쪽 메시지 입력 후 체크마크(✓) 클릭 → 커밋
- 동기화 아이콘(🔄) 클릭 → pull/push
- Pull Request는 (GitHub Desktop과 마찬가지로) 브라우저에서 생성 — 또는 "GitHub Pull Requests and Issues" 확장 설치 시 VSCode 안에서도 가능

(터미널 명령어에 익숙해지면 언제든 터미널로 넘어가셔도 무방합니다.)

## 개발 환경 설정 (초안 — 세부 사항은 진행하며 업데이트 예정)

**1. 저장소 클론**

- GitHub Desktop 사용 시: "Add" → "Clone repository"에서 `mulkko` 저장소 선택 후 clone (버튼 클릭만으로 가능, 터미널 불필요)
- 터미널 사용 시:
  ```bash
  git clone <저장소 주소>
  cd mulkko
  ```

**2. 이후 단계 (터미널 필요 — GUI로 대체 불가)**

```bash
# 패키지 설치
pip install -r requirements.txt

# 환경변수 설정
# 루트: .env.example을 복사해서 .env로 저장 후 값 채우기 (DB 접속 정보, API 키 — git에 올리지 않음)
cp .env.example .env

# frontend: 마찬가지로 .env.example을 복사해서 .env로 저장
cd frontend
cp .env.example .env
cd ..

# 실행 (백엔드 — FastAPI, 기본 8000번 포트)
python -m backend.main

# 실행 (사용자용 프론트엔드 — React, 별도 터미널에서)
cd frontend
npm install
npm run dev

# 실행 (관리자용 프론트엔드 — Streamlit, 별도 터미널에서)
streamlit run frontend-admin/app.py
```
