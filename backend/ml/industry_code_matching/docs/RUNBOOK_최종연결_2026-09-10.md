## 1. 최종 연결 순서 (크레딧 있는 키를 `.env` 에 넣은 뒤)

```bash
cd mulkko_industry_code_matching
cp .env.example .env          # OPENAI_API_KEY 채우기, EMBEDDING_MODEL=bge-m3 확인

# --- 상태 점검 ---
python -c "from industry_matcher import health; print(health())"
#   chroma_doc_count 14627, reference_rows 1612 이면 정상

# --- (1) ⑥ 스모크: 실제 1건 (~$0.03) ---
python business_matching/match_business_code.py \
  --seed "직접 볶은 원두로 손님에게 커피를 만들어 파는 카페" \
  --problem "동네에 스페셜티 커피를 마실 곳이 없다" \
  --solution "매장에서 바리스타가 에스프레소 음료를 제조해 현장 판매하고 원두도 소매한다" \
  --offline 예
#   -> 결과 상태 "추천_가능", 대표 "커피 전문점(552303)" 나오면 OK
#   프롬프트가 이상하면 `match_business_code.py` ACTIVITY_SYSTEM / RERANK_SYSTEM 손보고 재실행 (건당 ~$0.03)

# --- (2) ⑤ 골든셋 초안 200건 (~$0.3, 30분) ---
python business_matching/build_gold_draft.py            # gold_draft_v1.csv
#   먼저 스모크: python business_matching/build_gold_draft.py --dry   (20건)

# --- (3) 사람 검수 : gold_draft_v1.csv 열어서 ---
#   auto_check != OK 인 행 먼저, 사람_확정_primary / _secondary / _note 채우고
#   사람_검수완료 = Y.   (혼자, 5~10시간. category 별로 나눠 하면 편함)

# --- (4) 검수분 -> 평가셋 ---
python business_matching/finalize_gold.py               # gold_set_v3.csv

# --- (5) ⑦ 전체 파이프라인 평가 + 문헌 대조 (~$1.5) ---
python business_matching/eval_pipeline.py --gold business_matching/gold_set_v3.csv
#   -> data/outputs/eval_pipeline_gold_set_v3.json
#   Top-1 / Recall@3 / MRR / result_state 분포 / 추천_가능 버킷 정확도
#   문헌 기준: 추천_가능 ~55% · 그 버킷 ≥90% · 전체 Top-1 65~80%

# --- (6) (선택) 임베딩 A/B : OpenAI vs bge-m3 (~$0.01) ---
python business_matching/compare_retrieval.py --model text-embedding-3-small --gold business_matching/gold_set_v3.csv
python business_matching/compare_retrieval.py --model bge-m3 --gold business_matching/gold_set_v3.csv
```

## 2. 새 API 계약 (백엔드 연동)

```python
from industry_matcher import match_business_code, warm_up

warm_up()   # 서버 기동 시 1회 (bge-m3 GPU 로드 포함)

result = match_business_code(
    seed,                    # Q1 사업 아이템 (5~200자)
    problem_or_opportunity,  # Q3 문제/기회 (5~300자)
    solution_approach,       # Q4 해결 방식 (5~300자)
    is_offline_store=None,   # Q5: True(오프라인 매장) / False(온라인·서비스) / None(미입력)
    region="",               # Q6 지역: 업종 판정에 미사용, 통과만
)
```

### 출력에 새로 생긴 필드 (`result["representative_business"]`)

| 필드 | 값 | 용도 |
|---|---|---|
| `result_state` | `"추천_가능"` / `"사용자_확인_필요"` / `"정보_추가_필요"` | 결과 화면 분기 |
| `clarifying_question` | 문자열 (또는 "") | `사용자_확인_필요` / `정보_추가_필요` 일 때 화면에 표시 |
| `state_reason` | 디버그용 사유 | 로깅 |

- `revenue_model` 입력 **없음** (실제 폼에 수익모델 슬롯이 없어 제거).
- `business_code` = 국세청 6자리. `confidence` (high/mid/low) 는 유지.
- `alternatives` (최대 3), `additional_businesses` (0~2) 는 기존과 동일.

### 3상태 판정 규칙 (튜닝 파라미터 없음)

- `정보_추가_필요` : 후보 pool 비었음 OR 구조화가 `product_service` 를 못 뽑음
- `사용자_확인_필요` : 상위 후보 3개가 대분류 계열(제조/도소매/정보통신) 2개+ 에 걸침 OR `compute_confidence == low`
- `추천_가능` : 그 외
