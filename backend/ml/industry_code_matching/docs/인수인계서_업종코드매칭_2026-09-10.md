# 2. 호출 방법 (백엔드 코드)

**`service.py` 를 쓰면 됨** (캐싱 + 프론트용 납작한 응답까지 처리). 원본 `match_business_code()` 를 직접 쓸 필요 없음.

```python
from service import predict, warm

# 서버 기동 시 1회 (bge-m3 GPU 로드 등, ~10초)
warm()

# 요청마다
out = predict(
    seed,             # PSST Q1: 사업 아이템 (5~400자)
    problem,          # PSST Q3: 문제/기회 (5~500자)
    solution,         # PSST Q4: 해결 방식 (5~500자)
    is_offline_store=None,   # PSST Q5: True / False / None
    region="",               # PSST Q6: 지역 — 업종 판정 미사용, 통과만
)
```

- **동기 함수.** 내부에서 OpenAI(구조화 1회 + 활동별 재판정 1회) + 로컬 bge-m3 검색.
- **응답 시간 8~25초** → 워커/큐에서 처리하거나 타임아웃 30초+.
- 무거운 로딩(참조표·Chroma·bge-m3·OpenAI 클라이언트)은 `lru_cache` 로 프로세스당 1회만. `warm()` 이 미리 데움.
- 입력 길이 위반 → `{"ok": false, "error": "..."}` (예외 아님). OpenAI 오류는 전파.

# 3. 반환 스키마 (`predict()` 출력)

```jsonc
{
  "ok": true,
  "state": "추천",                       // ★ "추천" | "확인필요" | "정보부족"  (화면 분기)
  "question": "",                        // ★ state != "추천" 일 때 표시할 문장
  "primary":     { "code": "552303", "name": "커피 전문점", "confidence": "high" },
  "alternatives":[ { "code": "552205", "name": "생맥주 전문점" } ],   // 최대 3, "이 업종 아니면?"
  "additional":  [ { "code": "154901", "name": "커피 가공업", "confidence": "mid" } ], // 부가 0~2
  "raw": { /* match_business_code() 전체 응답 — 로깅/디버깅/재학습 로그용 */ }
}
```

- 검증 실패: `{"ok": false, "error": "seed: 3자입니다. 허용 범위 5~400자"}`
- `raw` 안에 `activities`(구조화 결과), `models`, `input`, 각 업종의 `ai_predicted_score` 등 전부.
- **사용자가 대표 업종을 바꾸면** 백엔드가 그 선택을 DB에 저장 → 재학습·재보정 로그.

# 4. 결과 3상태 → 프론트 처리 (계획서 §8)

| `state` | 언제 (내부 규칙) | 프론트 화면 |
|---|---|---|
| **추천** | 원문검색 1위 == 재판정 선택 AND 역할경계 아님 (전체의 ~36%, 이 버킷 정확도 97%) | 대표 업종 크게 + 근거 + 대안 후보. "[이 업종으로 시작] [다른 후보]" |
| **확인필요** | 상위 후보가 제조/도소매/SW 경계에 걸침 또는 신뢰도 low (~60%) | 대표 + 대안 2~3개 나란히 + `clarifying_question` 표시 |
| **정보부족** | 구조화가 "이 설명으론 업종 특정 불가" 판정 (~4%) | **업종 코드 숨기고** `clarifying_question` 표시, Q4 재입력 유도 |

⚠️ **`추천_가능` 이어도 자동 확정 금지** (계획서 §9-1). 최소 "맞아요?" 확인 1회. 항상 대안 후보 노출 (US Census BEACON 방식).

# 5. 백엔드 통합 시 주의

| 항목 | 내용 |
|---|---|
| ~~호출마다 재로드~~ | **해결됨.** `load_reference` / `load_lookup` / `open_chroma` / `_openai_client` 에 `lru_cache` 적용. `warm()` 이 예열. |
| **GPU** | bge-m3 임베딩은 GPU 권장 (RTX 4060 8GB에서 검증). CPU도 되지만 느림. GPU 없으면 `.env` `EMBEDDING_MODEL=text-embedding-3-small` 로 바꾸고 `python business_matching/build_business_code_docs_chroma.py` 로 OpenAI 인덱스 재구축 (성능 약간 하락). |
| **비용** | 요청당 gpt-5-mini 입력 ~1만 토큰 + 활동별 재판정. 대략 요청당 수십 원. 임베딩은 로컬(bge-m3)이라 0. |
| **동시성** | 동기 + 느림 → 큐(Celery 등) 필수. |
| **user_selected_code / changed_by_user** | 사용자가 대표 업종을 바꾸면 백엔드가 이 필드 채워서 DB 저장 → 나중에 재학습·재보정용 로그. |
| `KMP_DUPLICATE_LIB_OK=TRUE` | Windows conda 환경에서 torch/mkl 충돌 회피용 (embedders.py가 자동 설정). Linux 서버면 무관. |
