# 업종코드 매칭 — 평가 기준의 문헌 근거표

작성 2026-09-10 · 대상: `mulkko_industry_code_matching` (PSST → 국세청 6자리 업종코드)

---

## 0. 이 문서가 답하는 것

> "파이프라인이 쓰는 임계값, 논문 근거 있는 숫자로 못 정하냐?"

**정리:**

| | 파이프라인(실행 코드) | 평가(⑦) |
|---|---|---|
| 문헌 숫자를 쓰나 | **아니오** — 튜닝 파라미터 0개 | **예** — 측정값의 합격선(pass/fail bar) |
| 어떤 숫자 | 구조적 규칙 + `compute_confidence` 기존 보정값(이 시스템 전용) | 아래 §2 표 |

핵심: 문헌은 **"신호 임계값"을 안 준다**(§4 참고). 대신 **"운영 목표치"**(자동화율, 버킷 정확도, 정확도 천장)를 준다. 그 목표치를 ⑦에서 측정값과 대조한다.

---

## 1. 파이프라인이 실제로 쓰는 판정 (문헌 숫자 없음)

### 1.1 결과 3상태 — `decide_result_state()`

| 상태 | 조건 | 숫자? |
|---|---|---|
| 정보 추가 필요 | 후보 pool이 비었음 **또는** 구조화 LLM이 `product_service`를 못 뽑음 | 없음 (있냐/없냐) |
| 사용자 확인 필요 | 상위 후보 3개가 대분류 계열(제조 / 도소매 / 정보통신) 2개 이상에 걸침 **또는** `compute_confidence == "low"` | 없음 (계열 수 ≥ 2) |
| 추천 가능 | 그 외 | — |

"정보 추가 필요 시 되묻는다"는 설계는 NIOSH 대화형 코딩 방식과 동일 (§2-F).

### 1.2 Q5(매장 운영) 반영 — `store_conflict()`

오프라인 매장인데 후보 대분류가 **제조업 / 농업·임업·어업 / 건설업 / 운수·창고**면 → 기존 `role_fit`의 [상충](=2)으로 취급 → 이미 있는 `_ROLE_RANK_DELTA[+12]`로 순위 뒤로(완전 배제 아님).
→ 새 숫자가 아니라 **논리적 배제**: 손님이 걸어 들어오는 매장의 대표 업종이 공장·농장일 수 없음.

### 1.3 `compute_confidence()` 내부 컷 (기존 팀 코드, 유지)

`rank ≥ 4` 하향 / 한쪽 검색만이면 하향 / `retrieval_margin < 0.06` 하향 등.
→ **이 시스템 전용** 보정값 (`calibrate_confidence.py`, gold_v2 240건). 문헌값 아님. 순환적 gold라 무름 → ⑦에서 재보정 대상.

## 2. 문헌 근거표 (평가 합격선)

| # | 지표 | 문헌 값 | 출처 | 우리 적용 |
|---|---|---|---|---|
| A | **자동코딩 비율** (production rate) | 산업코드 약 **56%** 자동 배정 | 미국 Census, ACS 산업·직업 자동코딩 (2012) | "추천 가능" 상태가 전체의 **약 55%**가 되도록 규칙/게이트 점검 |
| B | **전자동(100% production) 정확도** | **65% → 78%** (알고리즘별, ISCO-88, 독일) | Schierholz & Schonlau (2021), *JSSAM* 9(5) | 전 건 자동 코딩 시 기대 정확도 밴드. 현재 Top-1 67%가 이 안 |
| C | **사람 코더 간 일치 (세분류, 4자리)** | 퍼센트 일치 **51~77%**, κ **0.56~0.70** | ISCO-88 다기관 비교; NIOCCS 4자리 | **정확도 천장.** 6자리에서 80%+ 는 비현실적 목표 |
| D | **사람 코더 간 일치 (2자리)** | κ **0.84** | NIOCCS (하드 코더 합의 vs 고신뢰 코드) | 대분류(역할) 수준은 높게 맞아야 정상 |
| E | **"자동 확정(사람 검토 없음)" 버킷 목표 정확도** | 통상 **≥ 90%** | 직업·산업 자동코딩 운영 관행 (NIOCCS 고신뢰 버킷 등) | "추천 가능" 버킷의 목표 정확도 |
| F | **정보 부족 시 추가 질문** | (방법) 응답에 분류할 정보가 부족하면 시스템이 추가 질문 | NIOCCS (대화형 코딩) | "정보 추가 필요" 상태의 근거 |
| G | **랭킹 후보 리스트 + 사용자 선택** | (방법) 하나로 강제하지 않고 순위 매긴 후보 제시 | 미국 Census BEACON; 영국 ONS ClassifAI | 대표 1 + 대안 후보 (이미 반영) |
| H | **자동 수락 확률 임계값** | **0.8** (단, "데모용"으로 명시) | occupationCoding 툴박스 (Schierholz) | 참고만. 우리 신뢰도는 보정된 확률이 아니라 채택 불가 |
| I | **질문 문구가 성능에 영향** | 구체적 문구 유도 시 자동코딩 정확도 향상 | Question framing 연구 (2025) | Q4 문구 "무엇을 만들거나 제공하고, 무엇을 팔거나 이용료를 받나요" 유지 근거 |

### 캐비아 (그대로 쓰면 안 되는 이유)

- **B·C·H는 "직업(occupation)" 코딩, 독일/미국 데이터**다. 우리는 "산업/업종", 한국, KSIC 기반. 방향·규모는 참고되나 값을 그대로 이식하면 안 된다.
- **A(56%)만 "산업(industry) 코딩" 값**이라 가장 이식성이 높다.
- C의 κ 0.56~0.70은 직업 4자리. 산업 세분류도 같은 연구들에서 비슷한 수준으로 보고되나 KSIC 6자리에 대한 직접 수치는 아니다.
- H(0.8)는 저자가 "for demonstration"이라고 못박음.

## 3. ⑦ 평가에서 측정값 ↔ 문헌 대조

골든셋(사람 검증 200건)에 파이프라인을 돌린 뒤:

| 측정 항목 | 문헌 대조 | 미달 시 조치 |
|---|---|---|
| "추천 가능" 상태 비중 | A: 약 55% | 규칙 조정 (역할 경계 판정 완화/강화) |
| "추천 가능" 버킷 실측 정확도 | E: ≥ 90% | `compute_confidence`의 low 조건 강화 |
| 전체 Top-1 | B: 65~80% 밴드 | 밴드 안 = 정상. 아래면 검색·재판정 개선 |
| Recall@3 | C 참고 (사람 일치율 상한 인식) | — |
| 대분류(역할) 정확도 | D: 높아야(κ 0.84 수준) | role 판정 로직 점검 |

계획서 §10.5 (A~E 비교) · §10.6 (지표 목록)이 이 분야 표준 평가와 일치.

## 4. 문헌이 **주지 못하는** 숫자

| 항목 | 왜 없나 |
|---|---|
| 절대 cosine 유사도 임계값 (`MIN_TOP1_COSINE` 류) | 임베딩 모델마다 유사도 스케일이 달라 **전이 불가**. 보편값을 제시한 논문 없음 |
| 1위–2위 cosine margin 임계값 | 동일 이유. `compute_confidence`의 0.06은 이 시스템·이 gold 전용 보정 |
| KSIC 6자리 특정 신뢰도 컷 | 한국·KSIC·PSST 조합의 선행 연구 부재 → ⑤ 골든셋으로 자체 보정 |

→ 그래서 파이프라인 판정을 **구조적 규칙**으로 짜고(§1), 숫자가 필요한 지점은 ⑦에서 **우리 데이터로** 보정한다.
