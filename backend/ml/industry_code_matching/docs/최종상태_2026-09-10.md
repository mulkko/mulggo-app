## 2. 성능 — **확정** (사람 검수 골든셋 `gold_set_v3`, 90건 층화)

| 지표 | **값** | 문헌 기준 |
|---|---|---|
| **Top-1** (대표 업종 = 정답) | **70.0%** | 65~80% (Schierholz 2021) — **밴드 안** |
| **Recall@3** (정답이 대표+대안 안) | **82.5%** | 사람 일치 상한 51~77% — **초과** |
| MRR | 0.57 | |
| **정보부족 감지** | **100%** (10/10) | NIOSH follow-up |
| **자동확정** (앙상블 게이트 A) | **커버 36% / 정확도 97%** | ~55% / ≥90% — 정확도 크게 상회 |

> 참고: 검수 전 잠정치는 Top-1 63% / NONE 감지 0% 였음. **골든셋 라벨이 나빠서 낮게 나온 것** — 진짜 정답지로는 70% / 100%.

**핵심**:
- 70% Top-1 (6자리 세세분류) 은 문헌 범위 안, 사람 일치율(51~77%) 상단.
- **앙상블 게이트**: "원문검색 1위 == 재판정 선택 AND 역할경계 아님" → 자동확정. 두 독립 신호 일치 시만이라 **정확도 97%**.
  커버 36% (나머지 64%는 "확인 권장" — 대안 + 질문 노출).
- 게이트 옵션 (`ensemble_gate.py` A~E 표): A 36%/97%(현재) · B +high 26%/100% · C top3 56%/80%.
  → `23_..._v3.py` `_AUTO_REQUIRE_HIGH` / `decide_result_state` 로 조정.

## 3. 그래서 제품은 이렇게

- `result_state` 를 **"AI 추천 (확인 권장)"** 으로 취급. `추천_가능` 이어도 자동 확정 금지 (계획서 §9-1과 동일).
- 항상 **대안 후보 2~3개 + "이 업종이 아니라면?"** 노출 (이미 반환됨). BEACON/ONS 방식.
- `사용자_확인_필요` → `clarifying_question` 화면 표시.
- `정보_추가_필요` → 재입력 유도. (단 이 상태는 현재 거의 안 뜸 — §5 참고)

## 4. 새 API 계약

```python
from industry_matcher import match_business_code, warm_up
warm_up()

r = match_business_code(seed, problem_or_opportunity, solution_approach,
                        is_offline_store=None, region="")
rep = r["representative_business"]
#   rep["business_code"]          국세청 6자리
#   rep["business_name"]
#   rep["confidence"]             high | mid | low
#   rep["result_state"]           추천_가능 | 사용자_확인_필요 | 정보_추가_필요
#   rep["clarifying_question"]    확인/정보부족일 때 표시할 문장 (아니면 "")
#   rep["alternatives"]           [{business_code, business_name}, ...] 최대 3
#   r["additional_businesses"]    부가 업종 0~2개
```

`.env`: `OPENAI_API_KEY` + `EMBEDDING_MODEL=bge-m3` + `LLM_MODEL=gpt-5-mini`.
서버 연동 주의: `match_business_code()` 는 호출마다 reference/chroma/bge-m3 를 다시 잡는다. `warm_up()` 예열 + (권장) 모듈 전역 캐시 리팩터. 응답 8~25초, 워커/큐 처리.
